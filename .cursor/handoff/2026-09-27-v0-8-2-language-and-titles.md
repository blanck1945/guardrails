# Plan: v0.8.2 — clearer check titles with an action, and a configurable language for review comments

**Handoff:** `.cursor/handoff/2026-09-27-v0-8-2-language-and-titles.md`
**Context:** `guardrails/CHANGELOG.md` (v0.8.0, v0.8.1); `DECISIONS.md` D-027 (coverage), D-042; `.cursor/handoff/2026-09-24-guardrails-context.md` (environment and gotchas). The user's answers: the comment language must be **configurable**, and they like the new titles below. Left open since the original plan ("language of the comments").

## Objective
1. Rewrite the fixed texts produced by the mechanical checks so that each title says what is wrong in plain words and each body ends with the action to take (the current title "No colocated test for RepositoryBadge.tsx" uses internal jargon, is a bare noun phrase and does not say what to do).
2. Add a `language` option (`"en"` default, `"es"`) that controls the language of every review text the code generates, and tells the model to write its own findings in that language.

## Who writes which text (keep this in the design)
- **Written by code, no model, no cost:** titles and bodies of check findings, the summary header and counts, the coverage line and the details block (table headers, statuses, legend, incomplete reasons), the "Also at" text, the low-confidence observations block, the cost footer, and the cloud failure notices. These get message templates in both languages.
- **Written by the model (Z.ai GLM today):** the title, body and suggestion of model findings and the free notes. These follow the language through one added instruction in the prompt (single and agent), no extra call.
- The text of rules in `rules.md` is written by the user in their own language and is never translated; it is quoted as is.

## Decisions made
1. **Config.** `language: "en" | "es"` in `.guardrails/config.json` (default `"en"`), read from the **base** commit like the rest of the config, with safe parsing (an invalid value falls back to `"en"` and reports an error). CLI: `--language en|es` overrides the config for `guardrails review`. No env var.
2. **One message module.** A single module (for example `src/core/i18n/messages.ts`) with typed message functions for `en` and `es`; every user-facing string generated by code goes through it. Adding a message without both languages must fail the type check or a test. Identifiers, rule ids, file paths, code, field names, the label `check`/`model` **keywords** and JSON keys are never translated (the legend explains them in the chosen language, the two words stay as they are so the tables stay searchable).
3. **New check texts** (English shown; write the Spanish equivalents with the same structure):
   - `colocated-test`: title `Missing test file: {file} has no test next to it`; body keeps the rule text and ends with `Add {expectedTestPath}.` (derive the expected name, e.g. `src/components/RepositoryBadge.test.tsx`, from the file extension: `.tsx` gives `.test.tsx`, `.ts` gives `.test.ts`).
   - `forbid-import`: title `Forbidden import: {specifier}`; body keeps the rule text and ends with `Remove or replace this import (see the rule above).`
   - `forbid-pattern`: title `Forbidden pattern in added code: "{match}"`; body keeps the rule text and ends with `See the rule above.`
   - `max-lines`: title `File too long: {file} has {n} lines (limit {max})`; body keeps the rule text and ends with `Split the file.`
   Keep the severity emoji, the `Rule {id} ({source})` citation line and the anchors exactly as they are. (Rule-specific titles, for example an optional `title:` per rule in `rules.md`, are out of scope; mention it in the CHANGELOG "Next".)
4. **Model language.** Add to both prompts (single and agent, `src/core/prompt.ts`, `src/core/agent/prompts.ts`) one instruction when the language is not English: write the title, body, suggestion and notes in that language; keep code, identifiers, file paths, rule ids and text quoted from the repository unchanged. English keeps the current prompts byte for byte (no change in behaviour or cost).
5. **Cloud and CLI wiring.** Cloud reads `language` from the base config and passes it to `reviewDiff`, the summary, the coverage renderer and the failure notices; the CLI human output honours it. The hidden markers and JSON output are language independent.
6. Do not change what is detected, presets, thresholds, anchors, dedupe or costs. All existing English outputs must stay identical except the four check titles/bodies of decision 3 (list every existing assertion you must edit and why).

## Risks and edge cases
- The model may ignore the language instruction for a finding; note any case in the report.
- Long Spanish texts can push the coverage line over 220 characters: the existing truncation must still hold ("+N more").
- Message templates with plurals and numbers: keep them simple (avoid grammar that depends on gender or count where possible).
