## Decisions made
1. **Merge duplicates by meaning, not by distance.** Two findings are the same problem when they share file and ruleId (or, when neither has a rule, the same file and a title similarity above the existing Jaccard threshold) regardless of how far apart their lines are. They become ONE finding: highest severity, highest confidence (+0.1 if both passes saw it, as today), the anchor of the more precise one, and a line in the body such as "Also at lines 25, 31." listing the other locations. Only merge across passes and across near-identical titles; two different problems under the same rule in the same file (different titles) stay separate.
2. **Anchor to the quoted text.** For each finding, look at its `evidence` snippets and any backtick or quoted text in title/body; if a snippet matches exactly one ADDED line of that file in the diff, use that line as the anchor. If several lines match, choose the first; if none matches, keep the model's line (then the existing "nearest commentable line" behaviour applies). Never anchor to a line that is not commentable.
3. **Structured summary.** The review summary is generated by code, not taken from the model's notes: first line "**Guardrails** · mode <mode> (<source>)", then counts ("N findings: A from checks, B from the model"; plus "M merged duplicates" when relevant), then at most two lines taken from the model's notes, trimmed. If the model part did not complete, say so as today.
4. **Cost visibility.** `review.analyzed` must log mode, passes, input/output/cached tokens, costUsd (null if the model has no price) and ms. Add an optional footer line to the PR summary ("Cost ~US$0.02 · 38 s · 2 passes") only when env `GUARDRAILS_SHOW_STATS=1`; default off (public repos may not want it).
5. Do not change presets, thresholds or the label mechanism.
